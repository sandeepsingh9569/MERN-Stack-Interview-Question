## 1. What is Express.js?
**Answer:**  
Express.js is a minimal and flexible Node.js web application framework that provides a robust set of features to build web and mobile applications. It simplifies handling routes, requests, and responses.
```js
const express = require('express');
const app = express();
app.get('/', (req, res) => res.send('Hello World'));
app.listen(3000);
```

---

## 2. What are the advantages of using Express.js?
**Answer:**  
- Simplifies server creation in Node.js.  
- Provides robust routing.  
- Middleware support.  
- Large ecosystem.  
- Integrates easily with databases and templating engines.

---

## 4. What is middleware in Express.js?
**Answer:**  
Middleware functions are functions that have access to the request, response, and `next()` function. They can execute code, modify requests/responses, end response cycles, or call the next middleware.
```js
app.use((req, res, next) => {
  console.log('Middleware executed');
  next();
});
```

## 1. Authentication vs Authorization

**Theory:**
Authentication verifies who a user is (login). Authorization determines what an authenticated user is allowed to do (permissions/roles). Both are essential in building secure APIs. Authentication usually returns a token or session; authorization checks that token/session against stored permissions.

**Code Example (Auth middleware stub):**

```js
function ensureAuthenticated(req, res, next) {
  if (req.user) return next();
  res.status(401).json({ error: 'Unauthorized' });
}
```

---

## 2. Sessions vs JWT (stateless vs stateful)

**Theory:**
Sessions are stateful — server stores session data (in memory, DB, or Redis) and issues a session id via cookie. JWTs are stateless — token contains claims and can be validated without server-side storage (unless using blacklisting). Sessions are easier to revoke; JWTs scale well across services but require careful handling of rotation and revocation.

**Code Example (session store):**

```js
const session = require('express-session');
app.use(session({ secret:'s', store: new RedisStore({ client: redisClient }) }));
```

---

## 3. Implementing JWT authentication (login + token)

**Theory:**
On login, validate credentials, sign a JWT with a secret (or private key), include minimal claims (user id, roles), and set short expiry. Use HTTPS, and consider refresh tokens for long sessions.

**Code Example:**

```js
const jwt = require('jsonwebtoken');
app.post('/login', async (req,res)=>{
  const user = await User.findOne({email:req.body.email});
  if(!user) return res.status(401).send('Invalid');
  const token = jwt.sign({ sub: user.id, role: user.role }, process.env.JWT_SECRET, { expiresIn: '15m' });
  res.json({ token });
});
```

---

## 4. Refresh tokens & token rotation

**Theory:**
Refresh tokens are long-lived tokens stored securely (httpOnly cookie or DB) used to obtain new access tokens. Token rotation means issuing a new refresh token on each use and invalidating the old one to mitigate theft. Store refresh tokens server-side for revocation.

**Code Example (refresh endpoint outline):**

```js
app.post('/token', async (req,res)=>{
  const { refreshToken } = req.body;
  // verify against DB, issue new access + refresh token, invalidate old
});
```

---

## 5. Secure storage for refresh tokens (DB vs cookie)

**Theory:**
Store refresh tokens in DB mapped to user and device, enabling revocation. Storing them in HttpOnly, Secure cookies reduces XSS risk but still require server-side verification to revoke compromised tokens.

## 6. Password hashing & salting (bcrypt)

**Theory:**
Never store plaintext passwords. Use a slow adaptive hashing algorithm like bcrypt/argon2 with salt to defend against brute-force and rainbow table attacks.

**Code Example:**

```js
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 12);
const ok = await bcrypt.compare(plain, hash);
```

## 7. Implementing role-based access control (RBAC)

**Theory:**
RBAC assigns roles to users (admin, editor, user). Middleware checks if user roles include required role for the route. Keep authorization logic centralized.

**Code Example:**

```js
const permit = (...allowed) => (req,res,next)=>{
  const { role } = req.user;
  if(allowed.includes(role)) return next();
  res.status(403).send('Forbidden');
};
app.get('/admin', ensureAuthenticated, permit('admin'), (req,res)=>res.send('ok'));
```

---

## 8. Attribute-based access control (ABAC) & policies

**Theory:**
ABAC bases access on attributes (resource owner, time-of-day, IP). Policies evaluate attributes for fine-grained control. Useful when RBAC is insufficient for complex conditions.

## 9. Middleware patterns (application-level, router-level, error-handling)

**Theory:**

* Application-level: `app.use()` runs for all requests.

## 14. CSRF protection (csurf)

**Theory:**
CSRF attacks force authenticated users to perform unwanted actions. For stateful apps (cookies/sessions), use CSRF tokens (e.g., `csurf`). For stateless JWT APIs, require double-submit cookie pattern or avoid sending credentials automatically.

**Code Example:**

```js
const csurf = require('csurf');
app.use(csurf({ cookie: true }));
app.get('/form', (req,res)=> res.render('form', { csrfToken: req.csrfToken() }));
```

## 15. Secure cookies (HttpOnly, Secure, SameSite)

**Theory:**
Set cookies with `httpOnly` to prevent JS access (mitigate XSS), `secure` to only send over HTTPS, and `SameSite` to restrict cross-site sending (Lax/Strict) to mitigate CSRF.

**Code Example:**

```js

```
